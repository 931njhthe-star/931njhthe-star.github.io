ORDER OPS + RESILIENT OPERATIONSMOA
01 / HOW IT WORKS

From group chat to one final coffee order

Paste a group conversation. AI interprets additions, cancellations, and changes; deterministic validation produces a consolidated order.

02 / MULTI-AGENT WORKFLOW

Three agents, one order workflow

LangGraph coordinates the workflow while specialized agents handle interpretation, menu matching, and review.

01 / AGENT

Intake Agent

Extracts add, change, and cancel intents

02 / AGENT

Menu Agent

Matches items and options; suggests candidates

03 / AGENT

Review Agent

Flags ambiguous orders for review

Rule-driven processing: link updates → validate quantities and options → settle and generate the order sheet. LLMs assist interpretation; rules govern final decisions.
03 / OVERVIEW

Two distinct layers, one service

An LLM-assisted order workflow for business logic, and a deterministic recovery workflow for operational resilience.

BUSINESS LAYER

Order processing · Multi-Agent

Chat input → Intake Agent → Menu Agent → rule-based validation and settlement → order sheet. The LLM proposes interpretations; deterministic rules determine menu validity and prices.

RELIABILITY LAYER · MY ROLE

Reliability · Auto Healing

Monitor → Diagnosis → Recovery Worker → Independent Verification. Recovery runs independently of the application and executes allowlisted actions.

SYSTEM ARCHITECTURE

From failure detection to verified recovery

Gateway, App A/B, interpreters, database, and the independent Healing Service.

04 / MY CONTRIBUTION

Recovery that stays outside the failing application

Owned fault detection, diagnosis, recovery and verification workflows, fault injection, incident records, and operational metrics.

01

Independent control plane

Separated recovery and operational controls from the application so they remain accessible during an application failure

02

Bounded actions

Separated request-level fallback from service-level actions, including process restart and circuit-breaker probing

03

Verification & observability

Linked fault injection, detection, recovery, independent checks, incident status, and MTTD/MTTR metrics

05 / RECOVERY PLAYBOOK

Six failure scenarios

Request-level fallback and service-level recovery have distinct responsibilities.

F-1

HTTP 5xx

Retry then switch interpreter

F-2

Request timeout

Timeout handling and alternate route

F-3

Process failure

App A/B failover, restart and checkpoint resume

F-4

Repeated failures

Circuit breaker, probe, operator approval

F-5

Invalid AI output

Regeneration and rule/schema validation

F-6

Menu DB failure

Reconnect and cached fallback
